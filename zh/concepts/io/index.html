    IO — 文档转换

    Scrivai 的 IO 模块负责将 PDF、DOC、DOCX 文件转换为 Markdown，以及将 Markdown 渲染回 DOCX。PDF 转换流水线支持多 OCR 后端、并发处理、自动容错和批量操作。

    架构概览

                            ┌─────────────────────┐
                        │   to_markdown(path)  │  ← 零配置快捷入口
                        └─────────┬───────────┘
                                  │
                        ┌─────────▼───────────┐
                        │  MarkdownConverter   │  ← 完整功能入口
                        │  (ConverterConfig)   │
                        └─────────┬───────────┘
                                  │
                  ┌───────────────┼───────────────┐
                  │               │               │
            ┌─────▼─────┐  ┌─────▼─────┐  ┌──────▼──────┐
            │ .doc/.docx │  │   .pdf    │  │   .pdf      │
            │ markitdown │  │ API 模式  │  │  GPU 模式   │
            │  (本地)    │  │           │  │  (MinerU)   │
            └───────────┘  └─────┬─────┘  └─────────────┘
                                 │
                    ┌────────────┼────────────┐
                    │            │            │
              ┌─────▼────┐ ┌────▼────┐ ┌─────▼────┐
              │MonkeyOCR │ │GLM-OCR  │ │ MinerU   │
              │(Docker)  │ │(云端)   │ │(HTTP API)│
              └──────────┘ └─────────┘ └──────────┘

    to_markdown() vs MarkdownConverter

    to_markdown() MarkdownConverter
    适用场景 快速单次转换 生产流水线
    配置方式 零配置（读取环境变量） 完整 ConverterConfig 控制
    多后端 从 env 读取默认后端 自定义后端优先级、调度策略
    批量处理 仅单文件 convert_batch() + 回调
    生命周期 每次调用创建/销毁转换器 跨多次调用复用 
    # 简单用法：零配置，从 env 读取 SCRIVAI_GLM_API_KEY / SCRIVAI_OCR_BASE_URL
from scrivai import to_markdown
md = to_markdown("report.pdf")

# 高级用法：完全控制
from scrivai import MarkdownConverter
with MarkdownConverter(
    mode="api",
    monkey_endpoints=["http://gpu6:7866", "http://gpu7:7867"],
    glm_api_keys=["key1", "key2"],
) as conv:
    md = conv.convert("report.pdf")

    两种模式

    API 模式（默认）

    使用远程 OCR 服务（MonkeyOCR 和/或 GLM-OCR）。PDF 被拆分为块并并发分派到各后端组。

    with MarkdownConverter(mode="api", monkey_endpoints=["http://localhost:7866"]) as conv:
    md = conv.convert("report.pdf")

    GPU 模式

    使用本地 MinerU 实例。适用于有 GPU 硬件且希望避免外部 API 依赖的场景。

    with MarkdownConverter(mode="gpu") as conv:
    md = conv.convert("report.pdf")

    MinerU 在未提供 URL 时会自动启动 mineru-router 进程。首次运行需下载模型（约 2-3 GB）。

    OCR 后端

    MonkeyOCR（自建 Docker 服务）

    部署在 Docker 中的自建 OCR 服务，每个实例绑定一块 GPU。

    • 并发: 每实例 4 个并发请求（默认）
    • 输入: PDF 文件通过 HTTP multipart 上传
    • 输出: 包含 Markdown 文件的 ZIP
    • 限速: 可选上传限速 upload_rate（字节/秒）
    with MarkdownConverter(
    monkey_endpoints=["http://gpu6:7866", "http://gpu7:7867"],
    upload_rate=512000,  # 500 KB/s 上传限速
) as conv:
    md = conv.convert("report.pdf")

    GLM-OCR（智谱云端 API）

    智谱 AI 的云端 OCR API。需要 open.bigmodel.cn 的 API key。

    • 并发: 每 key 3 个并发请求（默认）
    • 输入: Base64 编码的 PDF（每块 ≤ 100 页、≤ 50 MB）
    • 输出: Markdown 文本（兼容旧版和 ChatCompletion 两种响应格式）
    • 分块: 大型 PDF 发送前自动拆分
    with MarkdownConverter(
    glm_api_keys=["key1"],
) as conv:
    md = conv.convert("report.pdf")

    MinerU（本地 GPU 流水线）

    本地 OCR 流水线。智能分流：文字型页面直接提取，扫描件页面走 OCR。内置表格识别、版面分析和公式检测。

    • 并发: 每组 2 个文件（默认）
    • 多组: 通过 mineru_urls 配置多个 MinerU 实例
    • 自动启动: 未提供 URL 时自动启动本地 mineru-router
    with MarkdownConverter(
    mode="gpu",
    mineru_urls=["http://gpu1:8000", "http://gpu2:8000"],
    gpu_groups=2,
) as conv:
    md = conv.convert("report.pdf")

    ConverterConfig 参数参考

    ConverterConfig 是控制转换器所有行为的 dataclass。所有字段均有合理默认值。

    API 模式字段

    字段 类型 默认值 说明
    mode "api" | "gpu" "api" 处理模式
    dispatch "overflow" | "fallback" "overflow" 多后端调度策略
    api_backends list[str] ["monkey", "glm"] 后端优先级列表
    concurrency_per_group dict[str, int] {"monkey": 4, "glm": 3} 每后端每组并发数
    max_failures dict[str, int] {} 每后端最大失败次数（fallback 模式下非末尾后端必填）
    chunk_pages int 50 每块页数
    overlap_pages int 2 相邻块重叠页数
    chunk_strategy "file_first" | "interleave" "file_first" 批量分块调度策略

    GPU 模式字段

    字段 类型 默认值 说明
    gpu_backend str "mineru" GPU 后端名称
    gpu_concurrency_per_group int 2 每 GPU 组并发文件数
    gpu_groups int 1 GPU 组数量

    通用字段

    字段 类型 默认值 说明
    html_table "keep" | "to_markdown" "keep" HTML 表格后处理
    timeout int 300 单次请求超时（秒）
    retries int 3 最大重试次数
    retry_base_delay float 10.0 首次重试延迟（秒）
    retry_multiplier float 2.0 指数退避乘数

    故障处理字段

    字段 类型 默认值 说明
    failure_threshold int 2 每组连续失败触发冷却的阈值
    failure_cooldown_max float 300.0 最大冷却时间（秒）

    凭证字段

    字段 类型 默认值 说明
    glm_api_keys list[str] [] GLM API key 列表（每 key 一组）；为空时从 SCRIVAI_GLM_API_KEY 读取
    monkey_endpoints list[str] [] MonkeyOCR 端点 URL 列表；为空时从 SCRIVAI_OCR_BASE_URL 读取
    upload_rate int \| None None MonkeyOCR 上传限速（字节/秒）
    mineru_urls list[str] [] MinerU 实例 URL 列表

    多组并发

    每个后端可以有多个组——每个凭证（API key 或 endpoint）对应一个组。组之间通过 round-robin 负载均衡，每个组有独立的并发信号量和故障追踪。

    # 2 个 MonkeyOCR 实例 + 3 个 GLM key = 共 5 个组
# MonkeyOCR: 4 并发/组 × 2 组 = 8 槽位
# GLM: 3 并发/组 × 3 组 = 9 槽位
# 合计: 17 个并发块请求
with MarkdownConverter(
    monkey_endpoints=["http://gpu6:7866", "http://gpu7:7867"],
    glm_api_keys=["key1", "key2", "key3"],
) as conv:
    results = conv.convert_batch(pdf_files)

    调度策略

    配置多后端时，调度策略控制块如何分配到后端。

    溢出策略 Overflow（默认）

    优先填充主后端。当主后端所有组都繁忙或冷却中时，溢出到 api_backends 中的下一个后端。

    块到达 → 尝试 monkey[0] → monkey[1] → glm[0] → glm[1] → 等待 → 重试

    适用于：主后端优先但容量有限时最大化吞吐量。

    MarkdownConverter(
    dispatch="overflow",
    api_backends=["monkey", "glm"],
    monkey_endpoints=["http://gpu6:7866"],
    glm_api_keys=["key1"],
)

    降级策略 Fallback

    始终先尝试主后端。在某后端连续失败 max_failures 次后，降级到下一个后端。每个块有独立的失败计数器。

    块到达 → 尝试 monkey（最多 max_failures 次） → 降级到 glm → 尝试 glm

    适用于：偏好某一后端，但在持续错误时自动降级。

    MarkdownConverter(
    dispatch="fallback",
    api_backends=["monkey", "glm"],
    max_failures={"monkey": 3},  # 非末尾后端必填
    monkey_endpoints=["http://gpu6:7866"],
    glm_api_keys=["key1"],
)

    PDF 分块与合并

    大型 PDF 被拆分为重叠块以并行 OCR 处理。

    工作流程

    1. 拆分: PDF 按 chunk_pages 页拆分，相邻块重叠 overlap_pages 页
    2. 分派: 块并发分派到后端组
    3. 合并: 结果通过三层去重重组：
    4. 第一层 — Difflib 匹配（~90%）：在重叠区域找到最长匹配块，在中点处切分
    5. 第二层 — 比率估算（~9%）：Difflib 失败时，按重叠比率估算切分点并对齐到最近的段落边界
    6. 第三层 — 直接拼接（<1%）：未检测到重叠时的防御性回退

    配置

    MarkdownConverter(
    chunk_pages=50,      # 每块页数（默认）
    overlap_pages=2,     # 块间重叠（默认）
)

    小型 PDF（≤ chunk_pages 页）退化为单块处理，零额外开销。

    三层容错

    转换器实现了三层容错机制：

    第一层 — 单次请求重试

    每次后端调用最多重试 retries 次，指数退避（retry_base_delay × retry_multiplier^n）。HTTP 429 限流响应触发立即冷却，而非计入重试次数。

    第二层 — 单组冷却

    单个组连续失败 failure_threshold 次后，该组进入指数退避冷却（最长 failure_cooldown_max 秒）。同后端的其他组仍然可用。

    第三层 — 后端调度

    • 溢出模式: 某后端所有组都冷却中时，块自动溢出到下一个后端。若所有后端不可用超过 failure_cooldown_max 秒，抛出 OcrBackendError。
    • 降级模式: 某后端失败 max_failures 次后，块按优先级降级到下一个后端。

    批量处理

    convert_batch() 支持两种策略处理多个文件：

    file_first（默认）

    文件按顺序处理；每个文件内的块并发分派。失败的文件不阻塞后续文件。

    with MarkdownConverter(monkey_endpoints=["http://gpu6:7866"]) as conv:
    results = conv.convert_batch(["a.pdf", "b.pdf", "c.pdf"])
    # results: {"a.pdf": "...", "b.pdf": "...", "c.pdf": "..."}

    interleave

    所有文件的块进入同一个分派池，最大化跨文件的后端利用率。

    with MarkdownConverter(
    chunk_strategy="interleave",
    monkey_endpoints=["http://gpu6:7866"],
) as conv:
    results = conv.convert_batch(pdf_files)

    完成回调

    通过 on_complete 追踪每个文件的进度：

    def on_file_done(path: str, result: str | Exception) -> None:
    if isinstance(result, Exception):
        print(f"失败: {path} — {result}")
    else:
        print(f"完成: {path} ({len(result)} 字符)")

with MarkdownConverter(monkey_endpoints=["http://gpu6:7866"]) as conv:
    results = conv.convert_batch(pdf_files, on_complete=on_file_done)

    提供 on_complete 时，失败的文件静默从结果 dict 中省略。未提供时，任何失败都会抛出 OcrBackendError。

    错误处理

    IO 模块导出两个类型化异常：

    from scrivai.io import OcrBackendError, RateLimitError

try:
    md = conv.convert("report.pdf")
except RateLimitError as e:
    print(f"被 {e.backend} 限流 (HTTP {e.status_code})")
except OcrBackendError as e:
    print(f"后端错误: {e.backend}[{e.group}] — HTTP {e.status_code}")
    • OcrBackendError — OCR 后端错误基类。属性：status_code、backend、group。
    • RateLimitError — HTTP 429 限流错误（OcrBackendError 子类）。

    HTML 表格后处理

    OCR 后端通常以 HTML 格式返回表格。html_table 配置控制后处理行为：

    • "keep"（默认）：保留原始 HTML 表格
    • "to_markdown"：将简单 HTML 表格转为 Markdown 格式；含 rowspan/colspan 的表格保持 HTML（Markdown 无法表示合并单元格）
    MarkdownConverter(html_table="to_markdown")  # 需要 markdownify 包

    Word 文件转换

    Word 文件完全绕过 OCR 流水线：

    格式 处理流程
    .docx markitdown（本地，即时）
    .doc LibreOffice headless → .docx → markitdown
    .pdf OCR 后端（API 或 GPU 模式）

    环境变量

    简单场景下可通过环境变量代替 ConverterConfig 配置后端：

    变量 说明
    SCRIVAI_GLM_API_KEY GLM-OCR API key（单 key；多 key 请用 ConverterConfig.glm_api_keys）
    SCRIVAI_OCR_BASE_URL MonkeyOCR 端点 URL（单端点；多端点请用 ConverterConfig.monkey_endpoints）
    SCRIVAI_MINERU_URL MinerU router URL（留空则自动启动本地 router）

    环境变量在 ConverterConfig.__post_init__() 时读取。显式配置字段始终优先于环境变量。

    命令行

    # 基本转换（API 模式，默认）
scrivai-cli io convert --input report.pdf --output report.md

# GPU 模式（本地 MinerU）
scrivai-cli io convert --input report.pdf --output report.md --mode gpu

    CLI 使用默认 ConverterConfig 并从环境变量读取凭证。高级配置（多后端、调度策略、批量处理）请使用 Python API。
